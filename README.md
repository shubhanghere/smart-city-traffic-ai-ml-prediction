# Smart City Traffic AI — Real-Time 3D Traffic Digital Twin

A portfolio-grade, end-to-end smart-city traffic intelligence platform that combines a live 3D traffic simulation, a FastAPI AI backend, classical machine learning, traffic-signal optimization, analytics, and a computer-vision prototype.

The project is designed as a **New York-inspired digital twin** rather than a game: roads, towers, bridges, traffic lights, buses, cars, emergency vehicles, lane queues, and control-center telemetry are rendered in a professional dashboard while the backend continuously estimates congestion and recommends signal timings.

> **Important:** the 3D city is intentionally procedural and uses generic vehicle/building models. It does not bundle third-party vehicle logos or proprietary city assets. Replace the procedural assets with licensed assets later if you want photorealistic production visuals.

## What this project demonstrates

- Real-time traffic simulation in the browser with Three.js
- FastAPI backend with typed API models
- Synthetic-but-realistic traffic telemetry generation
- Random Forest congestion prediction
- Feature engineering from traffic volume, speed, occupancy, weather and incidents
- AI-assisted traffic-signal phase recommendation
- Queue-length, throughput, average-speed and travel-time analytics
- Anomaly detection using Isolation Forest
- Computer-vision prototype endpoint using OpenCV contour/shape analysis
- REST APIs for simulation, prediction, control and analytics
- Live frontend controls for traffic density, incidents, weather and AI control
- Responsive command-center UI with 3D visualization and charts
- Reproducible ML training script and saved model artifact

.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python ..\backend\ml\train.py

npm run dev

Open the Vite URL shown in the terminal, normally `http://localhost:5173`.

## ML model

The training script creates a reproducible synthetic traffic dataset and trains:

1. **RandomForestRegressor** — predicts congestion index from traffic features.
2. **IsolationForest** — identifies unusual traffic states.

The dataset is intentionally generated by code so the project can run without downloading a proprietary city dataset. For a production version, replace the synthetic generator with data from traffic cameras, loop detectors, GPS probes, public transport feeds, weather APIs, or an open city traffic dataset.

## Frontend controls

The command center includes:

- **Traffic density** — increases/decreases simulated vehicle volume.
- **Incident toggle** — creates an abnormal traffic condition.
- **Weather mode** — clear/rain/fog changes the traffic model features.
- **AI Traffic Control** — allows the backend policy to influence signal phase duration.
- **Simulation speed** — controls browser-side animation speed.
- **Manual phase buttons** — manually force north/south or east/west priority.
- **Reset** — returns the digital twin to a clean baseline.

## How the AI decision works

The backend receives lane-level telemetry such as:

- vehicle count
- average speed
- occupancy
- queue length
- weather condition
- incident status
- time-of-day

The ML model estimates a continuous **congestion index from 0–100**. The control policy then compares directional pressure and predicted congestion and chooses a phase:

```text
if north/south pressure is high:
    prioritize NORTH/SOUTH
elif east/west pressure is high:
    prioritize EAST/WEST
else:
    keep BALANCED timing
```

Green time is bounded so one direction cannot starve another.

## Computer vision prototype

`/api/vision/analyze` accepts an image and runs lightweight OpenCV analysis. It detects candidate vehicle-like regions using grayscale conversion, blur, edge extraction and contour filtering. This is intentionally a **prototype**, not a claim of production-grade object detection.

For a real deployment, the next step is a trained detector such as YOLO/RT-DETR with tracking (ByteTrack/DeepSORT) and camera calibration. The detector's counts would feed the same traffic-intelligence API used by this demo.

## Production upgrade path

The project is intentionally structured so the simulation can later be replaced by real feeds without rewriting the dashboard:

```text
Demo simulator
      ↓ replace with
Camera / loop detector / GPS / V2X / weather feeds
      ↓
Kafka / Redpanda
      ↓
Feature pipeline
      ↓
Online model inference
      ↓
Signal optimization service
      ↓
Traffic-signal controller / digital twin
```

Potential production additions:

- YOLO/RT-DETR + multi-object tracking
- SUMO/TraCI integration for research-grade traffic simulation
- Kafka/Redpanda event streaming
- Redis for hot state
- PostgreSQL/TimescaleDB for historical telemetry
- MLflow for model registry
- Prometheus/Grafana for observability
- Docker + Kubernetes deployment
- Azure/AWS/GCP deployment
- Reinforcement learning for adaptive signal control
- Real map/road geometry and licensed 3D assets
- Digital-twin synchronization with live IoT/V2X data
